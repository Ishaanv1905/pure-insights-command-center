# Data Quality Report

_Generated by `npm run data-quality` from `Case_Study_3_Pure_Insights_Monitoring.csv` on 2026-10-11._
_Every row is run through the same `processReading()` function the server uses, so these numbers match what the running app shows._

## Shape of the data

| Item | Value |
|---|---|
| Rows | 2000 |
| Columns | 10 (report_id, report_name, owner_email, last_refresh_status, monthly_active_views, snowflake_credits_consumed, avg_load_time_sec, aws_hosting_cost_usd, query_count_last_30d, concurrent_user_peak) |
| Distinct reports | 100 |
| Readings per report | 20 |
| Row order | round-robin: row *i* belongs to RPT_200 + (*i* mod 100) |
| Timestamp column | none (the server stamps `received_at` on arrival) |
| Rows rejected as malformed | 0 |

**Interpretation:** the file is 20 successive snapshots of the same 100 reports, not 2000 different reports. The app therefore stores every row as a *reading* (history) and keeps the latest reading per report as its *current state*. Values such as the owner and the refresh status change between snapshots of the same report, so "current state" always means "latest reading".

## Rules for anything else that arrives

| Situation | Response |
|---|---|
| Missing `report_id`, unknown status, a number sent as text, NaN, fractional count | **Rejected** with 400 and every error listed. The payload is saved in `rejected_payloads` and shown on the Data Quality page. |
| Any other negative numeric value | Accepted, flag `NEGATIVE_METRIC`, excluded from cost math. |
| Same `Idempotency-Key` sent twice | Second request returns 200 `duplicate: true` and stores nothing. |
